# Sửa lỗi 500 sau cập nhật — không cài lại dữ liệu

Ảnh File Manager cho thấy đúng vị trí public_html/nhansu và nhansu-private, nhưng thư mục cũ đã bị đổi thành assets.2757/lib.3523/bin.6401. Gói cập nhật trước chỉ chứa file thay đổi, nên tạo một thư mục lib/assets mới thay vì gộp có thể khiến thiếu file nền. Trường hợp thiếu file đã được tái hiện: PHP lỗi trước bộ bắt lỗi, trả nội dung trống và trình duyệt báo Unexpected end of JSON input.

Chưa đọc được phản hồi hosting trực tiếp từ môi trường phát triển do HTTP proxy 403; chưa xác nhận tên file thiếu cụ thể trên hosting. Gói sửa đầy đủ và trang kiểm tra giúp xác nhận nguyên nhân thực tế.

## Cách sửa

1. Giữ nguyên **config.php**, **storage**, database và các thư mục dự phòng có đuôi số. Không xóa hoặc nhập lại dữ liệu, không thay đổi WordPress.
2. Mở **bên trong nhansu-private**, upload **sua-loi-500-private.zip**, giải nén ngay tại đây. Thư mục lib/bin mới trong gói đã đầy đủ file, bao gồm rules.php và schema.php. Chọn Replace/Thay thế khi hỏi file trùng. Không để lồng thêm thư mục tên ZIP; nếu có, chuyển lib/bin ra trực tiếp dưới nhansu-private.
3. Mở **public_html/nhansu**, upload **sua-loi-500-public.zip**, giải nén ngay tại đây. Gói có đầy đủ assets cùng api.php, index.php và kiemtra-capnhat.php. Không đổi file .htaccess hoặc .user.ini hiện có.
4. Sau giải nén, file quan trọng cần nằm đúng:

```text
nhansu-private/
├── config.php                 (giữ nguyên)
├── storage/                   (giữ nguyên)
├── lib/
│   ├── rules.php
│   ├── schema.php
│   ├── bootstrap.php
│   ├── api.php
│   ├── people-finance.php
│   ├── bookings.php
│   └── ...                    (các file còn lại có trong gói)
└── bin/cron.php

public_html/nhansu/
├── api.php
├── index.php
├── kiemtra-capnhat.php
└── assets/
    ├── app.js
    ├── paths.js
    ├── api-response.js
    ├── style.css
    ├── vendor/
    └── ...                    (các file còn lại có trong gói)
```

5. Xóa hai ZIP đã upload trên hosting, giữ bản trên máy. Không xóa các thư mục dự phòng cũ ngay.
6. Mở **https://anhgaustudio.com/nhansu/kiemtra-capnhat.php**. Trang không cần đăng nhập, chỉ đọc phiên bản PHP và kiểm tra dấu vân tay các file, không kết nối database, không hiển thị mật khẩu/token.
7. Nếu có dòng đỏ: làm theo tên file cụ thể. THIẾU FILE thường là giải nén sai cấp; KHÔNG ĐỌC ĐƯỢC là quyền; KHÁC GÓI là chưa thay đúng file hoặc tải lên chưa đầy đủ. Thông thường file 644, thư mục 755 và đúng chủ sở hữu trên hosting; không cấp 777. Không tự đổi PHP toàn website WordPress chỉ để thử.
8. Mở **https://anhgaustudio.com/nhansu/api.php?route=%2Fstatus**. Kết quả bình thường khi đã cài là JSON có `"setup":false`.
9. Nếu API còn lỗi nhưng đã có JSON: gửi nguyên thông báo và mã tham chiếu; có thể đối chiếu mã đó trong PHP error log Hostinger. Không gửi nội dung config.php. Nếu vẫn là trang 500 trống cả khi các file đã đúng, kiểm tra PHP error log/WAF của hosting; mã trong ứng dụng không bắt được lỗi do web server/WAF xảy ra trước khi PHP chạy hoặc api.php bị cắt ngay chính file đầu vào.
10. Mở trang /nhansu/, nhấn **Ctrl+Shift+R** trên máy tính hoặc đóng tab rồi mở lại trên điện thoại. Phiên bản chân menu là v1.1.1.

Giữ nguyên Cron hiện có, không tạo thêm job. Hai gói không chứa config.php, storage, database hoặc file WordPress gốc. Gói private có tài liệu log nội bộ, chỉ đặt ngoài public_html.

## Những gì đã sửa trong mã

- Bắt lỗi từ trước khi nạp thư viện, kiểm tra file cần thiết và hàm bắt buộc.
- Có xử lý lỗi PHP cấp thấp để trả JSON an toàn khi có thể, không công khai đường dẫn tuyệt đối/chi tiết cấu hình.
- Giao diện không còn chỉ báo lỗi kỹ thuật JSON EOF khi máy chủ trả rỗng/HTML; hiển thị HTTP status và hướng dẫn kiểm tra.
- Gói sửa chứa mã nền đầy đủ thay vì chỉ file thay đổi.
- Trang kiểm tra độc lập không chạy migration hay chỉnh dữ liệu.

Đã kiểm thử trong Docker PHP 8.3/MariaDB: tái hiện lỗi gốc, các trường hợp thiếu/hỏng/không đọc được file, phản hồi HTTP rỗng/HTML, đăng nhập và tải JPEG/PDF/sao lưu. Chưa triển khai trực tiếp lên hosting của người dùng.
